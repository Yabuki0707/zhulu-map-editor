# 地图编辑器

《逐鹿》栅格底图的编辑工具。栅格是全图唯一的几何真源，一个像元对应一条记录，记录里有地块编码、块区编码、地形编码与气候编码四项。

编辑器只产出行政图，即地块、块区、地域三层。地形图与气候图由管线定稿，编辑器只读，见 `docs/adr/0001`。只读自然层的全部知识收在 `js/ro.js` 的一张表里，见下文。

## 打开

产物只有一个。双击 `启动编辑器.bat`，它先起本地服务 `serve.py`，再打开浏览器。

必须走这个服务，不能直接开文件。ES 模块在 `file://` 下会被 CORS 拦住，而且浏览器会缓存旧的 js；服务带了 `no-store`，两个问题都没有。

早先还有一个单文件版 `../栅格编辑器.html`，把 js 与数据内联成 base64，双击就能开。两份实现必然分叉，已按需求方意见整条删除，打包工具一并删掉。

这个服务不是纯静态服务，见 `docs/adr/0002`。图的真源只有一处，编辑器不持有副本：

| 网址 | 指向 |
|---|---|
| `/数据/<文件>` | `地图/地图数据/栅格/`，唯一真源 |
| `/草稿/<文件>` | `地图/待合入/`，编辑器存的草稿 |
| `POST /保存` | 只允许写 `地块编码.png`、`分区编码.png`、`台账.json` 三个文件，一律落进 `地图/待合入/` |

服务根仍是 `地图编辑器/`，所以网址依然是 `/index.html`。映射的是虚拟路径，没有把服务根上移。

## 改完的东西怎么进项目

编辑器的产出不直接写真源，中间隔一步：

1. 在编辑器里走 `⋯ → 存到待合入目录`，三个文件落进 `地图/待合入/`。
2. 跑 `python tools/import_editor.py`，它会校验草稿（比对指纹、检查地块是否压到海洋、块区是否越界、编号是否重复），然后备份，再合入真源，最后重写 `js/data.js`。

`import_editor.py --dry-run` 只校验不写。合入前一定备份到 `地图/待合入/备份-<时间戳>/`，回滚的办法是把那四个文件拷回原位。

启动时若 `待合入/` 里有草稿，编辑器会先问一句：用草稿继续，还是从正式版开始。草稿里只有行政图两层，地形与参考顶点永远读真源。

另有一条 `⋯ → 保存进度`（`Ctrl+S`），存的是浏览器 localStorage 里的增量存档，只用来防浏览器崩溃丢工作，不算产出。两条路各管各的，都在。

## 模式与单元

模式分视图（`V`）与编辑（`E`）。顶栏那一排是单元，其中三个可编辑，另有四个只读自然层，只在视图模式出现。

| 单元 | 键 | 底图着色 | 编辑对象 | 笔刷行为 |
|---|---|---|---|---|
| 地域 | `1` | 按地域色（未指派的半透明，地形透出） | 地块 | 拖过一片地块即改其地域归属，只改元数据，不动像元 |
| 地块 | `2` | 按相邻必不同的调色板（12 色，相邻地块一定不同色） | 栅格 | 把当前地块编码写进像元 |
| 块区 | `3` | 地块着色，块区着色压在上层 | 所属地块内的栅格 | 只在所属地块的范围内写入块区编码 |
| 样式 | `4` | 按显示类着色，即覆盖、形态、气候三轴合成出的名字与颜色，共 88 类 | 只读 | 没有笔刷 |
| 覆盖 | `5` | 按覆盖码着色，20 类，只看地表是什么 | 只读 | 没有笔刷 |
| 形态 | `6` | 按形态码着色，4 类，只看平陡 | 只读 | 没有笔刷 |
| 气候 | `7` | 热量带定色相，干湿定浓淡 | 只读 | 没有笔刷 |

样式与覆盖这两层，就是需求方要的“覆盖与样式两种模式”。形态与气候是另外两根轴的单轴视图。

这一层原来叫“地形”，2026-10-10 改名为“样式”。理由是：地形指那三个轴本身，样式指它们合成出来的样子。键 `k` 仍是 `"terrain"`，所以本地存档与键盘上的 `4` 号位都没变。

两种模式的操作不同：

- 视图模式：拖拽平移，滚轮缩放，点选。悬停时会贴出该格的覆盖、形态、热量带、干湿与显示类。
- 编辑模式：左键涂抹，右键选中（按住可连续拾取），空格或中键平移，笔刷是圆形并在地图上画出范围圈。编辑模式下单元条上不出现自然层，四个只读按钮连同分隔符一起隐藏；按 `4` 至 `7` 会提示切到视图模式；若存档停在只读层上，切回编辑模式时会自动落回“地块”。

## 笔与橡皮

顶栏的笔与橡皮是 SVG 图标，也可以按 `B`、`X` 切换。橡皮用于清掉当前单元的对象：地块清成 0，块区清成 0，地域清成未指派。只读自然层没有笔，也没有橡皮。

半径范围 1 至 50 格，上限 50 格约 415 km。顶栏有 SVG 滑杆，`[`、`]` 可微调，数值实时显示。半径 1 是单格，半径 2 是 3 × 3，落在圆内的格才落笔。

拖拽时按半径自动补点插值，快速划过也不会断线。一次拖拽算一步撤销。

## 块区

地块之下再分一层块区，用来表达一个地块内的港口、关隘、郡治片区等。

- 点 `＋ 新建` 建块区后，第一笔落在地块上时会自动认领该地块，也可以在右栏手选所属地块。
- 只允许在所属地块的范围内绘制，涂到别的地块上会被拒绝。
- 右栏可以查越界像元数（地块被重新划分后可能残留），并有“修正越界”一键清掉。

## 只读自然层

自然层由管线定稿，见 `docs/adr/0001`。地形由 ETOPO 高程与 Copernicus LC100 土地覆盖算出，气候由柯本分类分出。这两样将来都要做规则层的来源，例如基础地形代价。如果让人用笔刷随手改模拟底数，一笔划过就会静默改掉行军耗时，所以它们只读。

一层的全部知识都在 `js/ro.js` 的 `RO_LAYERS` 里，2026-10-09 抽出来的：

```js
k: 键,
n: 单元名, tip, title, sub,        // 单元元数据，顶栏按钮由它生成
rgb(字节, 气候码),                 // 一格的取色，满分辨率画布与金字塔都走它
bucket / oceanBucket / bucketCount / bucketLabel,   // 统计时一格记进哪个桶
panel(stats), legendNote(), insp(stats), note(stats)
```

载入时 `registerUnits()` 把它注册进 `config.js` 的单元表，于是顶栏按钮、左栏面板、右栏检视器、底图取色全由它派生。加一层只需在这张表里加一条，`config`、`ui`、`raster` 一行都不用动。

面板与检视器共用同一份统计：一次遍历 944 万格喂所有层，缓存 600 ms。海洋要不要计入由各层自己答，靠 `oceanBucket()`。样式层要计入，因为海洋是一类显示类，占全图 60.61%，少了它图例与页脚读数对不上。形态层与气候层不计入，因为海洋与海冰（覆盖 16）在这两根轴上都是无关位，混进来会让“平原”多出几百万格。判据统一在 `ro.js` 的 `noAxis()` 里，不要在层描述里各写一遍位移判断，那样会漏掉海冰。

拦截做在最底层，`paint.js` 的落笔函数第一行就是 `isRoUnit(unit)`。就算 UI 哪里漏了，比如快捷键或旧存档恢复的单元，也写不进去。

`⋯` 菜单里没有“导出地形 PNG”，编辑器不产出它，导出没有意义。

发现错格只能改管线的分类规则，即 `地图/栅格地形数据生成器/terrain.py`、`climate.py`、`display_class.py`，然后重跑生成。

编码见 `docs/adr/0006`、`0007`、`0010`，逐条判定规则见 `docs/地形覆盖判定规格.md`：

```
地形 = 一个字节
       高 5 位是覆盖，共 20 个值：
         0 海洋 1 淡湖 2 河流 3 冰川 4 密林 5 疏林 6 灌丛 7 草原 8 草甸 9 沼泽
         10 苔原 11 盐沼 12 滩涂 13 沙质裸地 14 砾质裸地 15 绿洲
         16 海冰 17 咸湖 18 盐漠 19 火山
       低 3 位是形态，共 4 个值：0 平原 1 丘陵 2 高原 3 山地
       字节 = 覆盖 × 8 + 形态，最大 19 × 8 + 3 = 155
       海洋仍是覆盖 0 且形态 0，即字节 0
       覆盖的顺序就是契约。0 至 3 四个码钉死不动，因为字节 0 用来判海陆，码 1、2、3 做细线保护
气候 = 一个字节两轴：热量带（2 位）与干湿（3 位）
       码 = 热量带 × 8 + 干湿，取值 0 至 31；干湿为 0 时整条读作寒带
显示类 = 覆盖 × 形态 × 气候 合成出的名字，共 88 类，见 docs/adr/0008、0012、0014
       密林与疏林各按热量带与形态分，另有灌丛、沙漠灌丛、苔原、高原草原、高山草原、
       亚寒带草原、亚热带草丛、荒漠与典型与草甸草原、稀树草原、热带与温带沙漠、
       热带与温带戈壁、寒漠、沙质裸地、砾质裸地、草甸、绿洲
       名字不存储：由 地图/栅格地形数据生成器/display_class.py 的按轴词表算出，
       编辑器按 display_lut 查表
```

显示类有两个契约键，都从 `js/data.js` 来，由 `地图/栅格地形数据生成器/editor_data.py` 的 `payload_from_meta()` 生成：

```
display_classes = [{n: 名字, c: 颜色}] × 88      // 名字与配色的唯一出处
display_lut[((覆盖 × 4 + 形态) × 32) + 码] = 类下标
                                                 // 2560 项，覆盖 20 × 形态 4 × 码 32
                                                 // 码 = 热量带 × 8 + 干湿；干湿为 0 时整条码归零
                                                 // 长度由覆盖类数推出，不写死
```

每个显示类都有独特色。任意两类的 CIE Lab 色差 ΔE 不小于 9，实测最小 9.7，由 `生成.py` 的契约断言与 `check_terrain` 的硬检查守着。改配色要看 `地图/栅格地形数据生成器/display_class.py` 的 ΔE 报告，不要凭眼睛判断。

海洋格不可落笔。覆盖为海洋的像元，三个可编辑单元一律跳过，收笔时会提示跳过格数。海洋是全图的海陆口径，即陆地等于 NE 陆地加湖泊加冰川区。地块层在构建期已按它裁过，所以地块压在海上不可能再发生，`import_editor.py` 也会再验一次。

## 图层与参考

快捷键：`T` 地形底图，`R` 参考（汉地唐州与其余单元边界），`P` 地块线，`K` 块区线。

参考层来自 `/数据/参考顶点.bin`，是矢量顶点图。汉地用唐 741 州面（Hartwell 339 州，反投影后折回窗口），其覆盖区内整条被子盖住的现代单元边界直接丢掉，避免两套线叠加。其余地区用源数据的单元边界（3682 个单元）。

用矢量而不用栅格，是因为老做法把边界烧成一张 8 位掩膜，1 px 线缩小后会整片消失或闪烁，还得再配一套 mipmap 金字塔来兜，而且顶点在栅格里根本读不出来。现在线宽按屏幕像素给，即 `1 / 缩放`，缩到全图不糊，放大不粗。放大到 12 倍以上会把原始顶点落成小方块，对着顶点改地块本来就是这一层的用途。

格式是 `ZLRV1` 魔数加环表，再加格坐标乘 8 的 uint16 顶点对（1/8 格约 870 m），约 1 MB。按需加载，第一次点“参考”时才取，失败只提示，不影响底图。

## 新建

“＋ 新建”只有一个按钮，建什么由当前单元决定，没有二级菜单。

| 当前单元 | 新建 | 落点要求 | 结果 |
|---|---|---|---|
| 地块 | 新建地块 | 先用右键在地图上选一格 | 那一格立刻归新地块，作为种子，接着用笔刷往外涂 |
| 块区 | 新建块区 | 先选中地块，再用右键选一格，且该格要在选中地块内 | 那一格归新块区，块区挂在该地块下 |
| 地域 | 不可新建 | 无 | 提示：地域是设计层固定的 93 个，请用地域单元把地块指派进去 |
| 只读自然层 | 不可新建 | 无 | 提示：自然层由管线定稿，编辑器只读，见 `docs/adr/0001` |

没选落点或落点不合规时不会静默失败，会提示先用右键在地图上选一格。撤销一步能同时回退像元归属与新建的台账。

## 右键选中

选中什么也由当前单元决定。右键不再是橡皮。

| 单元 | 右键选中 | 说明 |
|---|---|---|
| 地域 | 光标下的地块 | 地域的编辑对象本来就是地块 |
| 地块 | 那一格栅格 | 选中格记在 `selCell`，同时把该格所属地块设为当前地块 |
| 块区 | 那一格栅格 | 同时带上该格的地块与块区，切块区时会顺带把所属地块跟过去 |
| 只读自然层 | 不可选中 | 只读底图，没有“选中某个地形”这回事；点选看的是悬停贴里的那一格读数 |

按住右键拖动可连续拾取，视图模式下左右键都能点选。橡皮改由顶栏开关控制（`B` 是笔，`X` 是橡皮），不再占用右键。

## 飞地检测

一个地块或块区的像元可能分成几块互不相连的部分，成因有海岛、真实飞地，也可能只是手滑涂远了。

- 单个对象：右栏“连通块”一行给出块数。多于一块时列出每个碎块，带格数、`看`、`拆出` 三个按钮。`拆出` 把那一块变成新的地块或块区，有独立台账，自动命名为“原名·碎块”，一步可撤销。
- 全图：走 `⋯ → 飞地 / 多连通块检查` 弹出报告，列出所有多连通块对象，按碎块数排序，可一键跳过去。报告另附零像元台账清单，即种子台账里有、但栅格里一格都没落到的地块（小单元落在格心之间），可以“设为笔刷”手动画出来。地块清单里这类行也标着“空”。

边界线默认不画。大色块本身已经说明了分界，全图边界线在最密的地方只会变成一层毛边。需要时用顶栏的 `地块线`（`P`）或 `块区线`（`K`）打开。真正的分界看选中或悬停对象的轮廓，自动描边，1 至 2 px，随缩放保持像素宽。

## 数据模型

真源是栅格，每个像元写着一个地块编码与一个块区编码（`plot_id.png` 与 `dist_id.png`，编码为 `R + G × 256`）。一个地块包含哪些像元，是从编码反查出来的（`cellsOf`），台账里不存像元清单。

| 存什么 | 放在哪 | 说明 |
|---|---|---|
| 几何 | 栅格像元的编码 | 唯一真源，并集、邻接、边界长度、连通块都由它派生 |
| 地块语义 | 台账 `plots[id] = {名称, 地缘, 地域}` | 只有语义，没有几何 |
| 块区语义 | 台账 `blocks[id] = {名称, 所属地块}` | 所属地块是声明式约束，用于限定笔刷范围与判定越界 |

由此有一个必然结果：地块被重新划分后，块区会出现越界像元，即像元所属地块变了而块区的声明没变。右栏会报数并可一键修正。这不是脏数据，而是像元真源与声明约束两套口径的正常摩擦。

## 操作一览

- 单元：`1` 地域，`2` 地块，`3` 块区，`4` 样式，`5` 覆盖，`6` 形态，`7` 气候。后四个只在视图模式可用。
- 右键是选中，选中地块还是栅格由当前单元决定。
- 模式：`V` 视图，`E` 编辑。笔 `B`，橡皮 `X`。
- 半径 `[`、`]`。清单里前后切换对象用 `,`、`.`，在自然层上则是切换层。适应窗口 `F`，取消选中 `Esc`。
- 撤销 `Ctrl+Z`，重做 `Ctrl+Shift+Z` 或 `Ctrl+Y`，保存进度 `Ctrl+S`（存浏览器本地）。
- `⋯ → 存到待合入目录` 是正式交付，文件落进 `地图/待合入/`，再由 `tools/import_editor.py` 合入真源。
- 侧栏宽度可拖分隔条，布局记在 localStorage。

```
                      对只读层只留三条通用路径：按钮由表生成、面板调 layer.panel、检视器调 layer.insp
js/main.js            启动装配，含草稿探测与选择，另暴露 window.__editor API
serve.py              本地服务：静态文件 + /数据/ 与 /草稿/ 虚拟挂载 + POST /保存，禁缓存
启动编辑器.bat         双击即起服务并开浏览器
```

这里没有 `data/` 目录。图只有一份真源，在 `地图/地图数据/栅格/`，编辑器由 `serve.py` 的虚拟挂载去读，见 `docs/adr/0002`。编辑器自己的产出落 `地图/待合入/`。

依赖方向是 `config → ro → raster → refvec → state → render → paint → ui → main`，无环。`ro` 只依赖 `config`，因为只读层要注册回去。`raster`、`state`、`render`、`paint`、`ui` 都从 `ro` 取当前只读层怎么上色，谁也不许在别处按层名分叉。

## 图层与编码

| 层 | 文件 | 编码 |
|---|---|---|
| 地块层 | `/数据/地块编码.png` | 24 位 RGB，地块编码 = R + G × 256，`0` 表示无地块（海洋或未收录） |
| 块区层 | `/数据/分区编码.png` | 8 位灰度，存地块内的局部序号（1 至 255，`0` 表示无块区）。全局 id 见台账 `districts` 的 `(plot, local)` |
| 地形层 | `/数据/地形编码.png` | 8 位灰度，覆盖占高 5 位，形态占低 3 位，即 `覆盖 × 8 + 形态`。图例见 `js/data.js` 的 `cover_legend` 与 `form_legend`。只读 |
| 气候层 | `/数据/气候编码.png` | 8 位灰度，热量带 × 8 + 干湿，取值 0 至 31，干湿为 0 时读作寒带。只读 |
| 参考层 | `/数据/参考顶点.bin` | 矢量顶点，环表加格坐标乘 8 的 uint16。汉地用唐 741 州面，其余用源数据的单元边界，只作描图参考，非权威 |

地块层用 RGB 而不用 16 位灰度，是因为 canvas 会把 16 位灰度降成 8 位 RGBA，高字节会丢。P 社的 `province.bmp` 也是同样的办法。块区层与地形、气候层都是 8 位，够用。管线写 `L` 模式 PNG，编辑器导出的那张是 canvas 出的 RGBA，三通道同值。

## 数据契约

给管线用的四条约定：

- 几何真源是地块与块区的编码 PNG，不是矢量。地块的并集、邻接、边界长度都由它派生。
- 语义在台账里，用 `⋯ → 导出地块台账 CSV` 或 `导出块区台账 CSV` 得到。地块为 `id, 名称, 地缘, 地域, 像元数, 估面积km²`，块区为 `id, 名称, 所属地块, 像元数, 越界像元, 估面积km²`。运行时台账 `地图数据/栅格/台账.json` 的 `plots` 是 `{id, name, domain}`，其中 `domain` 写地域名。它是编辑器唯一产出、管线唯一接收的语义字段，由 `import_editor.py` 合入时写回。
- 存档只记与构建基准的增量（改动像元与台账），因此可以安全放进 localStorage。基准指纹里带了地块名指纹，换一批中文名即自动作废旧存档。
- 地形、海域、参考县界都是静态底图。道路与通行代价不入栅格，它们是动态且稀疏的，另用边表。

## 重新生成

```bash
python tools/build_editor.py --dump-units      # 单元与种子地块，名字已全量中文化
python 地图/栅格地形数据生成器/生成.py          # 栅格 + 参考顶点 + js/data.js
python 地图/栅格地形数据生成器/check_terrain.py # 抽查地形：已知地点断言与地块不入海的自检
```

编辑器改完的东西走另一条路合回去：

```bash
python tools/import_editor.py --dry-run        # 只校验草稿：指纹、不压海洋、块区不越界、编号不重复
python tools/import_editor.py                  # 校验，备份到 地图/待合入/备份-<时间戳>/，合入真源
```

`生成.py` 不再往编辑器拷图（真源唯一，见 `docs/adr/0002`），也不再把编辑器当输出目录，它只写 `地图编辑器/js/data.js`。两处生成 data.js 的代码收在 `地图/栅格地形数据生成器/editor_data.py`，底图指纹的算法收在 `basetag.py`。两处各写一份必然分叉。

重跑 `生成.py` 会换掉底图指纹，于是所有基于旧底图的草稿与浏览器增量存档一起作废。这是预期行为，不是缺陷。草稿会被 `import_editor.py` 按指纹拒掉，并提示重做。

默认栅格为 1/19°（约 5.86 km），3819 × 2472，约 944 万像元；粗一档用 `--cell 0.075`。地形需要 `原始数据/高程与地表/全球土地覆盖_100米.tif`（1.6 GB，Copernicus LC100）与 `全球高程_ETOPO_60秒.tif`，气候需要 `原始数据/气候/koppen_geiger_tif.zip`。`--no-veg` 可跳过土地覆盖。

数据目录在 `../地图数据/`，下有 `原始数据/`、`基础单元.json`、`栅格/`、`运行态/`，目录与文件名都已中文化，路径的唯一出处是 `../../地图/栅格地形数据生成器/mapdata.py`。编辑器草稿在 `../待合入/`。
